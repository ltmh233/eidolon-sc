# Go 管理多作品目录，Python 暂时独占 SC 运行时与数据库

独立维护的项目将支持多个作品，并逐步以 Go 实现通用核心。此次从只读目录切入，不把现有 Python 业务规则整体翻译一遍。

- Go 从可信 `work.json` 注册作品，默认作品固定为 `sc`。新内容包只需添加文件；启动时完整校验，失败则不启动。不做动态代码插件或在线安装。
- 新 API 的角色标识为 `work_id:local_id`。旧 API 的裸标识仍只代表 SC，存量 SQLite 标识不重写。
- SC 的 TOML 校验、目录展示规则、人设、世界设定仍由 Python 负责。Go 只通过既有公开 `/api/characters` 适配 SC，不另抄一套生日、读音、组合、立绘和招呼规则。
- 新 DLC 的目录、世界设定由 Go 真正加载并提供 HTTP API；人设保存在包内，但不通过公开目录暴露。没有对话执行器接入。
- 新作品不允许落入旧 SC 运行时。作品路径下未实现的 RAG、记忆等 API 返回 501，写入返回 405；未知作品返回 404。旧 API 明确指定非 SC 作用域时拒绝。不能据此宣称已经完成多作品 RAG。
- 过渡入口为一个可选 Go HTTP 进程，Next.js 的 `BACKEND_URL` 指向它。旧 HTTP 请求流式转发到原 Python；WebRTC 媒体仍直达 Python/coturn，不经过 Go。生产配置默认不启用。
- Go 不连接 SQLite。Python `Database` 单写线程、事务、迁移与备份责任全部保留（ADR-0028）。本阶段无数据库迁移。

ADR-0002 的跨角色共享记忆继续适用于现有 SC。下一阶段必须将其收窄为“同一作品内共享”；在完成 schema、删除、导入导出与检索作用域迁移前，不开放第二作品的聊天。账号和 OAuth 身份保持全局共享。

额外代价是一份 Go 进程及一跳本地 HTTP。无需消息队列、第二数据库或每作品进程。Go 故障会影响经过它的旧 API，因此先本地验收，再单独决定上线；回滚只需恢复前端原 `BACKEND_URL`，不用恢复数据库。

替代方案：直接让两种语言修改同一 SQLite 业务状态，会违背现有单写责任；先把全部通用模块在 Python 重构，再翻译 Go，会延长双套规则维护期；此次均不采用。

2026-10-25 补充：第二阶段首条切片缩小上文“世界设定仍由 Python 负责”的范围。显式配置 `EIDOLON_WORLD_SNAPSHOT` 时，Go 的 SC 适配器负责 world.json 静态解析、类型校验和规范化，以带作品身份及格式版本的私有文件交给 Python；Python 只物化已有 World 运行时模型，继续计算日期相关 Prompt 与检索资料。选用离线原子发布文件，避免为静态内容引入常驻 RPC 依赖和公开资料端点。快照加载失败须阻止启动，不能自动回退原始文件；未配置时保留旧路径供回滚。角色 TOML、素材派生、SC 公开目录适配、全部事务和数据库责任不变。快照与角色配置需作为同一内容版本准备，修改 world.json 后须重新导出并重启 Python。具体边界与验收见 [世界内容切片](../migration/go-content-world-slice.md)。

2026-10-25 第二条切片补充：`EIDOLON_CHARACTER_SNAPSHOT` 启用 Go 导出的统一 v2 角色/世界内容，取代运行时角色和读音 TOML 解析、人设/事实源文本读取；输入清单摘要检查仍留在磁盘上的礼物与素材版本。Python 保留事实分段、语气提示、音频地址和所有用户业务计算，并共用原 Character 物化校验以兼容回滚。Go 原生 `static-characters` 仅公开明确的基础字段，不用内部快照替换完整目录 JSON；完整目录的素材 URL 派生仍依赖 Python。这样避免在 Go 再实现一套语音/素材规则。此项更新不声称完整角色目录已去依赖，详见 [角色内容切片](../migration/go-content-character-slice.md)。

2026-10-25 第三条切片补充：v3 将完整礼物静态定义纳入同一角色/世界私有内容批次，Python 不再为该模式解析礼物 TOML，仍负责背包、赠送、好感度及事务。完整 SC 展示目录由离线 Python 发布器复用旧 API 的纯投影算法生成，以内容摘要绑定，Go 通过嵌套字段白名单加载后原生服务；不复制音频哈希或素材生成算法。该目录无需正在运行的 Python，但构建元数据仍需要 Python，旧裸 `/api/characters` 与素材文件端点继续属于 Python。启用 `EIDOLON_CATALOG_DISPLAY` 可在 Python 启动前验证投影与部署素材基址。两个发布文件各自原子替换，不提供跨服务热更新事务；采用不可变版本目录、显式配置、启动校验和发布前响应比对。保留 v1/v2 与无快照回滚，不迁移数据库及对话引擎。证据和限制见 [第三条切片验收](../migration/go-content-final-slice.md)。
